## 4. Avalonia 专有技术 → reactor 替代方向

| 技术 | 位置 | 替代方向 |
|---|---|---|
| **Viewbox 等比缩放** | `SettingsPageView.axaml:376`、`AbbrPageView.axaml:19,29,57`、`KeymapPageView.axaml:35,93`、`ActionEditorPanel.axaml:26,31,33` | **无等价物** ⇒ 响应式布局 / `ScaleTransform` / 显式 DPI 缩放（PoC 未覆盖，**需专项验证**） |
| **WrapPanel chips** | `SettingsPageView.axaml:674-687`、`AbbrPageView.axaml:29`、`SelectedActionPageView.axaml:46,143`、`ActionEditorPanel.axaml:155,188` | `VariableSizedWrapGrid`（PoC 已覆盖）或 `ItemsRepeater` 自定义布局 |
| **SelectableTextBlock + InlineUIContainer 链接** | `MarkdownRenderer.cs:77,96,116,184-188,336-379`、`HomePageView.axaml:30-57` | `RichTextBlock` + `Hyperlink`（需专项验证） |
| **ItemsControl/ListBox/ComboBox + DataTemplate** | 多处（SettingsPage 59 处 / SelectedActionPage 61 处等） | `ItemsRepeater`/`ListView` + keyed_children |
| **IValueConverter** | `Converters.cs`（16 处 XAML 引用） | reactor 无 converter 概念 ⇒ 在 `view()` 里直接计算 |
| **自定义控件 `Controls/*`** | HotkeyCapture / WindowPickButton / EditZoneHint / ActionEditorPanel / CommentSummaryPanel | 改为「函数返回 View」或 `Component` |
| **对话框 chrome / ModalBlur** | `DialogChrome.cs:28-59`、`ModalBlur.cs`、`DialogReveal.cs`、`DialogPlacer.cs` | `ContentDialog`（PoC 已覆盖）+ `WindowVisuals` |

| **Transitions / Animation** | `SettingsPageView.axaml:60-325`（12 处入场级联）、`RevealHeightMotion.cs:144-158`、`ComboDropdownMotion.cs:239-258` | `ThemeTransition::Reposition`（reactor）+ Storyboard（未暴露，需专项验证） |

## 7. 工作量最大的三块

1. **`Services/` 的 Win32 栈**（`WindowPickerSession` 891 行、`Services/Win32/*` 全部 P/Invoke）——深度绑定 Windows 原生 API；Rust 侧改用 `windows`/`windows-sys` 反而更自然。
2. **`ViewModels/`（26 项，约 240KB）**——逻辑可复用但需重接 reactor 的 Component/Message 体系；`MatchTypesDialogViewModel`(33KB)、`SettingsPageViewModel`(26KB)、`ActionEditorViewModel`(22KB) 为首。
3. **`Views/`（18 个 axaml ≈165KB，最大 `SettingsPageView.axaml` 59KB）**——Viewbox/手风琴阴影/动画最密集处，几乎全部 §4 条目落在此层。

> 权威契约基准：`Services/SettingsApiClient.cs` 的 12 端点清单 + `Models/ConfigModels.cs` 的 json 字段名。
