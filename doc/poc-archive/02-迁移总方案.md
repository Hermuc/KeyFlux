# KeyFlux 设置面板迁移总方案（Avalonia → Rust + windows-reactor / WinUI 3）

> 决策：用户已确认 **推翻「Avalonia 定案」**，走 **Rust + windows-reactor**（唯一能真正「集成 windows-rs」的路线）。
> 事实边界：`windows-reactor` = v0.100.0（0.x，约 1.2k 下载，2026-04 首发，2026-09 末更新，来源 crates.io）；API 模型见技能 `windows-reactor`。**该库极早期，下列设计含未核实项，均标注「待核实」。**

---

## 1. 总体策略：换实现，不换边界

```
┌─────────────── KeyFlux 引擎（不变） ───────────────┐
│  AHK v2 主引擎 (KeyFlux.exe) ── 生成产物/热键        │
│  Go 后端 (settings.exe) ── HTTP :KEYFLUX_PORT        │
│  配置真源 data/config.json                           │
└──────────────────────────────────────────────────────┘
                ▲ HTTP（协议串不变）
                │
    ┌───────────┴───────────┐
    │ 设置面板进程（被替换） │
    │  旧: Avalonia / C#     │
    │  新: Rust + reactor    │
    └────────────────────────┘
```

**核心原则**：只替换设置面板进程的语言/框架；Go 后端、AHK 引擎、`config.json`、HTTP 协议、部署目录结构**全部不动**。这样迁移风险被完全限制在「一个 HTTP 客户端 + 一套 UI」内。

## 2. 关键改造点

| # | 领域 | 旧（Avalonia/C#） | 新（Rust + reactor） | 风险 |
|---|---|---|---|---|
| 1 | 视图 | 18 个 `.axaml` | 18 个 `Component`（`view()` 返回 `View`） | 高：范式不同 |
| 2 | 状态 | 26 个 ViewModel + CommunityToolkit.Mvvm（双向绑定/命令） | `Component` 自持状态 + `Message` 单向流 | 高：MVVM→React 式需逐页重写 |
| 3 | 设计系统 | `Claude.axaml`（26 画刷/8 阴影/4 半径/3 ControlTheme）+ `ClaudePalette.cs` | Reactor 控件 builder + WinUI 3 主题资源（`ResourceDictionary`） | 高：**现有皮肤契约与像素级踩坑经验基本作废** |
| 4 | 材质 | 亚克力 `WindowSurface.Apply` 运行期改 alpha | WinUI 3 原生 **Mica/Acrylic（SystemBackdrop）** | 中：更原生，但调节方式不同 |
| 5 | 窗口/弹窗 | 8 个弹窗 + `DialogChrome.Apply`（Win32 P/Invoke）+ `ModalBlur.IsHost` | `context.window_frame(...)` + `windows`/`windows-window` 原生互操作 | 中：`window_frame` 能力边界**待核实** |
| 6 | 服务层 | `SettingsApiClient`(HTTP)、`ConfigSaver`(JSON 往返) | Rust HTTP 客户端 + `serde_json`（字段名逐字一致） | 中 |
| 7 | i18n | `Resources/i18n.json` + `I18n.cs` | 同格式 `.json`，Rust 侧读取 | 低 |
| 8 | 字体/图标 | MiSans、MDI ttf (`materialdesignicons.ttf`) 走 avares 资源 | `assets/` 嵌入 + `build.rs`/`include_bytes!` | 中（**待核实** reactor 的字体指定方式） |
| 9 | 错误处理 | CS8602 可空等 | Rust `Result`/`anyhow`（**待定**是否引入） | 低 |

> ⚠️ **最大不确定性**：Avalonia 侧有大量**像素级 headless 测试与皮肤契约测试**（`SkinContractTests`/`SettingsCardEffectTests`/`ScrollBarStylesTests`/`NavRebuildFlickerTests`/`TopFlareWingsAlignmentTests`），它们依赖 Avalonia 的 `CaptureRenderedFrame`/`RenderTransform` 等机制。Reactor **未核实到 headless 测试方案** ⇒ 这批测试**无法等价平移**，只能重构为「行为测试 + 人工视觉验收」。

## 3. 依赖调整

**移除**（随 `config-ui-avalonia` 退役）：
- `Avalonia` / `Avalonia.Desktop` / `Avalonia.Themes.Fluent` 11.3.20
- `CommunityToolkit.Mvvm` 8.4.2
- `PublishTrimmed`/`PublishReadyToRun` 等 .NET 发布开关

**新增**（Rust，版本以 `cargo add` 实际锁定为准，勿凭空填写）：
- `windows-reactor` = **0.100**（已核实）
- `windows-reactor-setup`（部署 Windows App Runtime，README 提及；**版本待核实**）
- `windows` / `windows-sys` / `windows-bindgen`（原生互操作，按需选型）
- JSON：`serde` + `serde_json`
- HTTP：**待定**（`ureq` 阻塞式更简单，或 `reqwest`；需与 Reactor 的运行时/异步模型匹配 —— **待核实** Reactor 是否自带 async 运行时）
- 错误处理：`anyhow`/`thiserror`（**待定**）

**构建/发布链调整**：
- `Makefile`：`buildClientAvalonia` → `buildClientReactor`（`cargo build --release`）；`sync-out` 的 UI 源从 `bin/ui`（.NET 自包含）改为 Rust 产物目录。
- `.github/workflows/`：`release.yml` 增 `dtolnay/rust-toolchain` + Windows App SDK Runtime 装载；`analyzers.yml` 由 `dotnet format` 换为 `cargo fmt --check` + `cargo clippy -D warnings`。
- 部署形态：从「.NET 自包含单目录」变为「原生 exe + 依赖 DLL + WindowsAppRuntime」。

## 4. 风险登记（按严重度）

| 级别 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 🔴 高 | `windows-reactor` 0.x、极新、下载量低、文档少 | API 变动、踩坑无处查、可能中途弃用 | 先 PoC；锁定版本；抽象一层薄封装隔离 Reactor |
| 🔴 高 | 无 headless 测试框架 | 现有像素级守护测试失效，回归能力下降 | 迁移期保留 Avalonia 版做**行为对照基线**；建立人工验收清单 |
| 🔴 高 | 设计系统重建成本 | 皮肤/描边/阴影/滚动条几何的历史裁定需重做 | 用 Fluent Design 技能 + 现有对比度基线表（记忆 5.13）做映射 |
| 🟠 中 | 本机无 Rust 工具链 | 无法构建/验证 | 前置安装 rustup + MSVC |
| 🟠 中 | Windows App SDK Runtime 部署 | 用户机器缺失则无法启动 | `windows-reactor-setup` 随包部署，纳入安装流程 |
| 🟠 中 | 启动/体积既有优化需重做 | 冷启动体验回退 | 迁移后专项度量 |
| 🟡 低 | DTO 字段名不一致 | 被 Go 全量落盘静默剥离 | 契约测试：与 Go/C# DTO 逐字比对 |
| 🟡 低 | 单 exe 交付/图标/计划任务重启 | 部署脚本回归 | 纳入回归清单 |

## 5. 不可逆点与回退

- **可回退**：迁移期 `config-ui-avalonia` 与 `config-ui-reactor` 并存，部署脚本可切换 UI 源（`bin/ui` 指向哪一边）。
- **不可逆**：一旦修改 `Makefile`/CI 把 UI 源切到 Rust 且删除 Avalonia 工程，回退成本高 ⇒ **该步必须放在最后，且由用户确认**。
