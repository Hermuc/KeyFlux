# 13 — 缺陷修复：CapsLock 失效 / 面板黑窗 / 选项页缺失

> 状态：**已完成**（2026-09-28）。三缺陷根因、修复与真机验证记录。
> 背景：用户在生产部署树 `D:\PortableApps\KeyFlux` 报告三缺陷。

## 1. CapsLock 不弹出命令框

**根因（复合）**：
1. **部署树缺运行时资源目录**：`bin\behaviors`（11 个内置行为包）、`bin\font`（MiSans）、
   `bin\html`、`bin\icons`、`bin\sound`、`tools\` 全部缺失 —— 部署按 `sync-out` 白名单
   配方（`*.ahk *.exe *.ps1 *.txt *.dll`）复刻，这些目录内容是非白名单扩展名。
   memory-export 四.16 本就警告 behaviors 须手工同步。`KeyFlux-CommandInput.exe`
   缺字体/行为包等资源无法常驻存活。
2. **data\config.json 误用仓库出厂样例**（55631B）而非用户真源（旧树 62220B）——
   违反「配置真源铁律」（memory-export 三.3）。
3. **排查过程中引擎实例被诊断清理命令误杀**（`Stop-Process -Name settings` 不分青红皂白），
   造成「引擎自灭」假象；计划任务重启后进程稳定（KeyFlux=1 CommandInput=1 settings=0 按需）。

**修复**：补 5 个目录（robocopy /MIR）+ `tools\`；`config.json` 换用户真源
（样例双备份：`%TEMP%\keyflux-sample-config.bak-20260928.json` + 部署树 `config.json.bak-sample`）；
`plugin-settings.json` 与用户 `custom_functions.ahk` 一并迁移；计划任务 `\KeyFlux` 重启。

**验证**：`KeyFlux-CommandInput.exe` 常驻存活（PE Subsystem=2 GUI，无控制台）；
`KeyFlux.ahk` 重新生成且 `/Validate` exit 0；前台直跑主脚本 12s 存活且
settings+CommandInput 都被正确拉起（证明脚本链路完好）。
**待用户真手确认**：按 CapsLock 单击弹命令框（合成事件验证受 IDE 提权前台干扰，未采信）。

## 2. 设置面板弹出黑色控制台窗口

**根因**：`backend.rs:199` spawn `settings.exe --headless` 未设 `CREATE_NO_WINDOW`
（`settings.exe` 为控制台子系统程序，PE Subsystem=3；旧 C# `CreateNoWindow=true`）。

**修复**：`std::os::windows::process::CommandExt::creation_flags(0x0800_0000)`。

**验证**：生产树无参启动面板（模拟引擎拉起），全屏截图无黑色控制台；面板正常连接后端。

**⚠️ 残留观察项**：回归截图曾捕到一闪而过的控制台黑窗（标题 = 部署树 bin 路径），
疑为 **CommandInput.exe（冻结二进制，GUI 子系统）按需 spawn settings.exe**（无隐藏标志）
的引擎既有行为，与面板无关、转瞬即逝。若复现，用 Process Monitor 抓父进程定位；
可行修法 = keyflux.tmpl / CommandInput 侧隐藏运行（需裁定）。

## 缺陷四：打开面板弹黑色控制台窗口（2026-09-28）

**现象**：引擎托盘菜单/`se` 命令打开设置面板时，弹出黑色控制台窗口（标题为面板完整路径）。

**根因**：面板二进制 PE 子系统为**控制台**（Subsystem=3）——`main.rs` 缺
`windows_subsystem` 属性，Rust 默认编译为控制台程序。引擎（GUI 进程，无控制台）经
`Functions.ahk:103` 的 `Run` 拉起面板时，Windows 为控制台子进程**新建**控制台窗口。
此前真机验证未暴露：从 PowerShell 启动时子进程**继承**父控制台，不新建窗口。

**修复**：`main.rs` crate 根加
`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
—— release（部署产物）为 GUI 子系统（与旧 C# 面板 `OutputType=WinExe` 对齐），
debug 保留控制台便于诊断。连带加固：GUI 子系统下顶层错误不可见（无控制台），
`main` 的 `run_component` Err 分支先落盘 `%TEMP%\keyflux-panel-error.log` 再 panic。

**验证**：release Subsystem = **2（GUI）**；仓库 `bin\ui` 按 buildClientReactor 语义
发布（robocopy 排除中间产物 + 改名 `KeyFlux.Settings.exe`）并 `/MIR` 同步生产树；
WMI `Win32_Process.Create`（GUI 父进程，模拟引擎拉起）启动生产树面板：
ConsoleWindowClass 窗口前后枚举 0→0（无黑窗），导航完整渲染
（使用指南/选中动作/插件/CapsLock/F 模式/Command/选项，即后端 Ready 已连接），
引擎托盘与 CommandInput 不受影响。evidence-gui-subsystem-launch.png。
闸门：167/167 + fmt/clippy 0 告警。
排查插曲：WMI 启动后面板进程消失两度误判为崩溃，实为操作者手动杀进程；
其余差异（TEMP 指向等）已排除。
