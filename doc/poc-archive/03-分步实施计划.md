## Phase 1 — 环境与 PoC（最高优先，先证可行性）

| 步骤 | 动作 | 验收 |
|---|---|---|
| 1.1 | 安装 rustup + MSVC 工具链；`rustc -V`、`cargo -V` 可用 | 命令回显版本 |
| 1.2 | 最小 PoC：`App::run_component` 起一个窗口，含 `TextBlock`/`Button`（照技能 `windows-reactor` 示例） | 窗口可显示、点击可触发 `update` |
| 1.3 | 验证 Windows App SDK Runtime 装载（`windows-reactor-setup`） | 目标机无 SDK 也能启动 |
| 1.4 | 验证 Reactor 能否承载：多窗口/弹窗、Mica/Acrylic、嵌入字体(MiSans)、HTTP 调用 | 每项给出结论（能/不能/绕行） |
| 1.5 | 记录 PoC 结论，回填 `02` 中所有「待核实」项 | 文档无遗留「待核实」 |

**门禁**：若 1.4 中「弹窗/材质/字体」任一无法满足 ⇒ **暂停并向用户报告**，重新评估路线（不硬推）。

## Phase 2 — 骨架与契约层（无 UI 逻辑）

| 步骤 | 动作 | 验收 |
|---|---|---|
| 2.1 | 建 `config-ui-reactor` crate 骨架（目录见规范 §3） | `cargo fmt --check`/`clippy -D warnings` 通过 |
| 2.2 | 实现 `models/`（DTO），字段名与 Go/C# **逐字一致** | 契约测试：与 `config-server` DTO 对账 |
| 2.3 | 实现 `services/`：HTTP 客户端（对接 `127.0.0.1:{KEYFLUX_PORT}`）、`ConfigSaver`（JSON 往返保真） | 单测：读-改-写往返字段无损 |
| 2.4 | 端口 `i18n`（沿用 `resources/i18n.json`） | 键数/引用对账与现有守卫等价 |
| 2.5 | 主题层 `theme/`：把 `ClaudePalette` 令牌映射到 WinUI 资源 | 令牌清单 1:1 覆盖（26 画刷/4 半径） |

**门禁**：2.2/2.3 通过前不得进入 Phase 3（契约错会污染后续所有页面）。

## Phase 3 — 逐页迁移（按依赖序）

顺序（先骨架页、后复杂页）：
1. 主窗口 + 导航（`MainWindow`/`BuildNav`）
2. 设置页（`SettingsPageView`）—— 含亚克力/材质
3. 使用指南页（`HomePageView` + Markdown 渲染四层 → Rust 版）
4. 模式页（`KeymapPageView`）
5. 缩写 + Command 页（`AbbrPageView`）
6. 选中动作页（`SelectedActionPageView`）+ 行为库
7. 匹配类型（`MatchTypesDialog*`）
8. 插件页（`PluginsPageView`）+ 插件市场/设置弹窗
9. 其余弹窗（ActionEditor/OverviewEdit/QuickSwitch/WindowGroup）

| 步骤 | 每页动作 | 验收（每页独立） |
|---|---|---|
| 3.x | 按旧 `View + ViewModel` 重写为 `Component`；接线 `services` | ① 与旧版**行为对照**（同一 config 下渲染/交互一致）② 人工截图验收 ③ `make check` 不回归 |

> 迁移期**每页保留 Avalonia 版为对照**，用同一份 `config.json` 做 A/B。
