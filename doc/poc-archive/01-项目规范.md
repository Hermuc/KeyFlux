## 2. 代码风格（闸门化）

两道强制闸门，任何提交前必须 `exit 0`：

```
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

- 格式化：`rustfmt.toml`（见 `scaffold/config-ui-reactor/rustfmt.toml`），`edition`/`max_width=100`/`imports_granularity=Crate`（若为 nightly-only 选项则降级为默认并注释说明）。
- Lint：`clippy.toml` + `Cargo.toml` 的 `[lints.clippy]`（见 scaffold）。
- **禁止**在代码里用 `#[allow(...)]` 掩盖新告警；如需例外，必须写明理由注释。

### 命名约定

| 对象 | 规则 | 例 |
|---|---|---|
| crate / 模块 / 文件 | `snake_case` | `config_ui_reactor`、`selected_action` |
| 类型 / trait / Component | `UpperCamelCase` | `SelectedActionPage` |
| 函数 / 变量 / 字段 | `snake_case` | `load_config` |
| 常量 / 静态 | `SCREAMING_SNAKE_CASE` | `DEFAULT_BACKEND_PORT` |
| 组件类型 | 后缀 `...Component` 或语义名 | `KeymapPage` |
| 消息枚举 | 后缀 `Msg` | `SelectedActionMsg` |

> 与既有 AHK 侧约定区分：AHK 的「函数名与变量名不得只差大小写」等铁律**不适用**于 Rust（不同语言），勿混用。

## 3. 目录结构（目标）

```
KeyFlux-main/
├─ config-ui-avalonia/          # 迁移期保留（对照基线），迁移完成后退役
└─ config-ui-reactor/           # 新建（Rust）
   ├─ Cargo.toml
   ├─ Cargo.lock                # 二进制应用 → 入库
   ├─ rust-toolchain.toml
   ├─ rustfmt.toml
   ├─ clippy.toml
   ├─ build.rs                  # 如需嵌入图标/资源（待定）
   ├─ assets/                   # 图标、字体(MiSans)、MDI ttf
   ├─ resources/                # i18n.json（沿用现有格式）
   ├─ src/
   │  ├─ main.rs                # App::run_component / run_with
   │  ├─ app.rs                 # 根组件 + 导航
   │  ├─ components/            # 每个页面/弹窗一个 Component
   │  ├─ services/              # HTTP 客户端、ConfigSaver(JSON 往返)、i18n
   │  ├─ models/                # DTO（json tag 与 Go 侧逐字一致）
   │  ├─ theme/                 # Fluent 令牌 → 设计系统映射
   │  └─ platform/              # windows-rs 原生互操作（窗口/DPI/计划任务读取等）
   └─ tests/                    # 集成测试
```

> ⚠️ 现有 `config-ui-avalonia/` 的 **18 视图 / 26 VM / 26 Service** 是迁移对象清单，逐项对照建 Component，勿遗漏弹窗。

## 4. 版本管理策略

1. **对外版本与 KeyFlux 联动**：发布仍走 `git tag v<ver>`（现有 `release.yml` 语义），设置面板随整包发布，**不单独发版**。
2. **内部 crate 版本**：`Cargo.toml` 的 `version` 与 KeyFlux 版本保持一致（或 `.0` 后缀），作为构建溯源。
3. **提交规范**：Conventional Commits（`feat:`/`fix:`/`refactor:`/`chore:`/`docs:`/`test:`），与现有仓库习惯对齐。
4. **CHANGELOG**：新增 `config-ui-reactor/CHANGELOG.md`，按版本记录可观测行为变化。
5. **锁定**：二进制应用 → `Cargo.lock` **必须入库**（保证 CI/本机可复现）。这与记忆里「.NET 构建不可字节复现」的教训相呼应：Rust 侧靠 `Cargo.lock` + 固定 toolchain 保证可复现。

## 5. 与现有 KeyFlux 契约的衔接（不可破坏）

| 契约 | 要求 | 来源 |
|---|---|---|
| HTTP 边界 | 设置面板仅作 `http://127.0.0.1:{KEYFLUX_PORT}` 客户端；Go 后端/引擎零改动 | 记忆「架构要点」第 6 条 |
| 协议串 | `KEYFLUX_PORT=` / `KEYFLUX_GUI_READY` / `KEYFLUX_BACKEND_EXITED` 语义不变 | 记忆「构建/部署」第 17 条 |
| 配置真源 | 仍读写部署目录 `data/config.json`；不引入第二真源 | 记忆「项目地图」第 3 条 |
| DTO 字段名 | Rust 模型的序列化字段名必须与 Go/C# DTO 契约**逐字一致**（否则被 Go 全量落盘静默剥离） | 记忆「踩坑-Go」第 9 条 |
| i18n | 沿用 `Resources/i18n.json`（松资源 + 键数守卫语义），不重定义键机制 | 记忆「踩坑-Go」第 8 条 |
